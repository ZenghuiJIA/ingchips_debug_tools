# AI-HIL Debugger v1.3.1

2026-10-23。本版按三批修复调试结果、任务生命周期和协议处理问题，保留原有页面布局。

## 第一批：操作与结果正确性

- HIL 的 SVD 断言按设备、外设和寄存器解析真实地址。读取失败、缺少读数、长度不完整均报告失败，不再用期望值代替实际结果。
- ING 烧录接口等待实际烧录和串口恢复流程返回。流水线不再等待固定 1.5 秒后误报成功。
- 内存编辑绑定已读取快照的地址和探针；改动选择后必须重新读取，多字节提交使用固定目标。
- 硬件快捷助手只执行完整命令，否定句、问句及缺少地址或数值的写操作不再触发硬件动作。存在多个目标时要求在专用工具页明确选择。
- JScope 重复启动返回忙碌错误。RPC 增加响应 ID 校验、读写超时和独立的进程终止路径，阻塞操作移出窗口线程。
- 删除 DWT 页面中的随机性能统计。函数耗时采集未接入，按钮停用；PC 统计改用目标支持的 DWT_PCSR，不再以运行中的核心寄存器读数冒充实时采样。

## 第二批：任务与连接

- 切换主标签保留已创建的任务页面、日志和状态。隐藏内存页、LCD 页停止自动刷新。
- 相同波特率重复打开串口复用已有连接；更改参数要求先断开。ING 烧录期间拒绝其他操作重新打开该串口。
- 后台 RTT/JScope 占用探针时拒绝冲突的 SWD 操作。桌面与 MCP daemon 使用同一探针文件锁，进程退出后由操作系统释放。
- 停止 JScope 只关闭自身采样流，不再关闭所有串口；RTT 和采样断线通知页面。
- 修复 TCP 标签关闭路由。连接或绑定失败返回错误；TCP Server 区分监听与连接，可接收后续客户端。
- UDP 保留最近发送方地址用于回复；尚未收到数据时说明无发送目标。当前 UDP 仍为监听/回复模式。
- HIL 固定本次执行的步骤，支持可取消延时、读断言重试和步骤超时判定。硬件操作超时后不抢跑后续步骤；SWD 的硬性截止时间由 daemon RPC 管理。

## 第三批：协议与验证

- 修正两线 DTM 的长度、载荷和 Test End 编码，等待设备应答后确认状态，接收统计来自结束应答。
- 当前 DTM 支持 1M PHY、0–63 字节和三个标准载荷；扩展 PHY 与单载波未接入，相关选项禁用。
- HCI H4 使用跨块缓存和长度组帧，支持拆包、粘包；串口文本使用流式 UTF-8 解码。
- 大快照分块读取完整范围并检查长度，快照对比绑定地址、大小和探针。Intel HEX 按地址解码，不再把文本字节当作内存数据。
- 读写内存正确传递 SWD 频率。SVD 继承访问属性和宽度，对读清零、特殊写入、只读/只写等情况阻止不安全的自动操作。
- 回归测试直接调用生产源码，覆盖命令解析、HIL 结果、写入目标、协议组帧、快照范围、探针占用及 RPC 超时/响应匹配。
- 发布脚本不再全局终止正在运行的调试进程，不再在构建失败后使用旧二进制冒充新包。ZIP 包含文件 SHA-256 清单。

## 验证范围与已知限制

完成前端类型检查与构建、Rust 单元测试、Python daemon 单元测试，以及冻结 daemon 的 MCP 握手、工具列表、错误返回和退出验证。协议及硬件调用使用模拟接口验证，没有对实际开发板执行烧录、复位或内存写入。

真实设备上的时序、热插拔、射频收发和 DWT_PCSR 支持情况仍需上板验收。实时 LR/调用者追踪、函数耗时采集和扩展 DTM 能力没有作为已实现功能交付。主标签保留状态会增加已访问页面的内存占用，原有固定内存预算不作为本版保证。

若旧程序正在占用工作区二进制，构建脚本保留旧进程；本版 ZIP 使用此次编译并验证的 daemon。请从本版解压目录启动桌面程序。
