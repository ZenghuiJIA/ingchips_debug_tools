# 嵌入式调试扩展实现方案

日期：2026-10-23。状态：待实施。

本文依据当前工作区的 HIL runner、串口协议与回放实现制定后续开发方案。本次交付仅新增本文，不表示下述 SDK、接口、解析器或设备适配器已经实现，也不改变当前发布包和运行进程。

## 1. 范围与交付边界

优先实现固件插桩、数据协议、离线分析和 HIL 编排。功耗仪器暂不接入实际设备，先完成数据契约、数据处理逻辑和适配器边界；电源暂未选型，先完成接口、控制状态机及故障处理。逻辑分析仪完全排除，不设计对应适配器、页面、协议、依赖或后续开发任务。

“插桩”指在目标固件中记录真实事件、时间戳和运行状态。“接口预留”指具有明确输入、返回值、失败语义和测试的底层实现。没有硬件驱动的操作返回不支持，不以空实现、固定数值或模拟成功代替。

| 功能 | 初版实现范围 | 初版不交付 |
| --- | --- | --- |
| 固件插桩 SDK | 有界事件记录、时间基准、构建标识、传输及平台适配接口 | 自动修改用户工程、默认插装所有函数 |
| 崩溃现场 | 现场格式、Cortex-M 捕获基础、可选保留 RAM 端口、分块导出、离线解析和证据包 | 任意芯片断电留存、任意固件完整调用栈和局部变量恢复 |
| RTOS 状态 | FreeRTOS 显式适配、任务快照、栈余量、可验证的运行计数 | 通用 TCB 布局猜测、多 RTOS 全覆盖、自动判定死锁 |
| 函数和中断耗时 | 手动范围插桩、上下文关联、耗时统计和预算断言 | PC 采样推导函数耗时、全系统无损指令跟踪 |
| 功耗仪器 | 能力接口、样本格式、导入、区间统计、积分、质量检查 | 实时设备接入、自动发现、具体厂商驱动 |
| 可控电源 | 能力接口、板卡与通道绑定、控制状态机、取消和恢复契约 | 具体电源/继电器驱动、真实电压扫描、微秒级断电控制 |
| 数据断点 | 保留既有建议为后续独立任务，本批只记录边界 | 本批实现或对外启用；它属于硬件调试能力，不用固件插桩替代 |

首批主机功能可通过记录文件、固定测试向量和可控测试适配器验证。目标固件的 RAM 开销、时序开销、复位留存及实际采集正确性，需要选定板卡后验收；没有实机证据的部分标记“实现但未上板验证”。

当前工作区存在较多未提交改动。以下是源码基线，不据此判断已安装桌面程序或 MCP 服务的版本。

| 现有位置 | 可复用内容 | 本方案需要补充的部分 |
| --- | --- | --- |
| `src-tauri/daemon/hil/runner.py`、`worker.py` | 后台任务、取消、独立日志、失败取证 | 插桩会话、分析动作、设备能力预检、资源恢复结果 |
| `src-tauri/daemon/hil/config.py` | HIL v1/v2 加载、严格字段检查、步骤快照 | 新动作契约、v3 资源绑定和迁移 |
| `src-tauri/debug-core/src/protocol.rs`、`capture.rs` | 协议处理、捕获记录 | 插桩帧编解码及错误记录，继续供桌面和 headless 共用 |

| `src-tauri/src/hardware/serial_manager.rs` | 串口/RTT 会话、接收与记录 | 把已接收字节交给插桩解码消费者，不额外打开设备 |
| `src-tauri/daemon/hardfault_analyzer.py` | 异常帧分析、符号定位、反汇编 | 面向离线内存的读取接口、构建匹配、结果可信度 |
| `src-tauri/daemon/rtos_tracer.py` | 从 ELF 识别 RTOS 和关键符号 | 真实任务数据导入、SDK FreeRTOS 端口及数据解释 |
| `src/components/CaptureAnalysis.vue`、`McuProfiler.vue` | 历史查看、已有分析入口 | 插桩事件、数据缺口及结果来源展示 |

现有 HIL 失败取证发生在主机发现失败之后，获取的是采集时刻的现场；目标已经复位时，这些寄存器不能替代历史崩溃数据。新的证据包要并列保留两种来源。

现有 HIL 取证会暂停目标且不自动恢复。新离线分析不连接设备；插桩采集不新增隐式暂停或复位。以后增加临时在线快照时，必须保存原运行状态，并在可靠清理路径中仅恢复本次暂停的目标。既有 HIL 失败后保持暂停的策略不因离线分析接入而暗中改变。

现有 `unwind_stack()` 包含扫描栈中疑似代码地址的逻辑。新报告区分“异常帧记录”“按展开规则恢复”“栈扫描候选”，不能把候选地址串成已证实的调用链。该调整限于结果契约和相关展示，不借此重写整个调试器。

## 3. 分层和资源归属

固件 SDK 负责生成事件；Rust 公共核心负责传输帧；Python 分析服务负责语义分析、证据包和 HIL；Vue 负责参数与结果展示。固件 SDK 不解析 HIL 测试脚本。

```text
固件插桩 / 崩溃保留区
  → 现有 UART 或 RTT 通道
  → 当前资源所有者的接收与原始记录
  → Rust 公共帧解码
  → Python 事件分析 / 离线现场 / HIL 断言
  → 结果文件、现有页面、CLI、MCP

测量文件 → 功耗分析服务 → 离线结果
HIL → 电源/功耗适配器接口 → 未安装驱动时拒绝执行
```

桌面手动串口/RTT 仍由已有会话持有资源；HIL 使用现有交接机制，由 worker 持有本次运行的串口和探针。新分析器仅订阅或读取字节记录，不自行连接硬件。HIL 初版先支持当前已有的 UART 采集路径；RTT 自动采集必须在会话交接与探针仲裁验证后另行启用。

未来仪器适配器归 Python 服务管理，桌面和 MCP 调用同一服务。工位配置必须声明仪器稳定 ID、通道、目标板 ID 和连接方式。串口型仪器的传输必须复用既有资源归属机制：HIL 中由 worker 持有，桌面入口先交接或返回占用错误，不允许另开串口争抢句柄。

每个采集任务固定 `job_id/run_id`、设备绑定和配置快照。跨进程资源租约覆盖物理设备，多个通道是否可并行由适配器明确声明；默认整台设备独占。页面卸载不释放后台任务的资源，关闭服务则按其任务关闭策略收尾。

## 4. 固件插桩 SDK

### 4.1 模块和平台边界

拟新增 `firmware/hil-instrumentation/`，使用可静态分配的 C 接口，不依赖动态内存和具体芯片 HAL。首批提供通用核心、Cortex-M 故障捕获基础及 FreeRTOS 适配层；芯片寄存器、链接区和 RTT/UART 实际发送由平台端口提供。

| 接口类别 | 拟定接口 | 约束 |
| --- | --- | --- |
| 初始化 | `hil_instr_init(config)` | 配置固定缓冲区、构建 ID、时间源和已支持能力 |
| 业务事件 | `hil_event(event_id, value)` | 数值参数固定宽度，不传主机需解引用的指针 |
| 耗时范围 | `hil_span_begin(id)`、`hil_span_end(token)` | token 绑定启动代次、执行上下文和嵌套实例 |
| 中断事件 | `hil_irq_enter(irq)`、`hil_irq_exit(irq)` | 显式接入 ISR；不替换用户中断向量表 |
| 任务快照 | `hil_rtos_snapshot()` | 从允许调用内核查询接口的任务上下文执行 |
| 传输排空 | `hil_instr_drain()` | 普通任务上下文、有界发送、传输失败可观察 |
| 故障保存 | `hil_crash_capture(context)` | 固定内存、不等待日志锁、不调用普通发送路径 |
| 平台端口 | 时间源、短临界区、发送、保留区读写 | 缺失能力不编译启用，不提供默认硬件地址 |

宏关闭时不产生记录，宏参数不求值。记录结构采用显式字节编码，禁止直接发送 C struct，避免填充、大小端和编译器 ABI 差异。

任务与普通 ISR 写入环形缓冲区时使用已定义的短临界区并保留原中断屏蔽状态；不使用可等待的互斥锁。NMI/HardFault 不写普通环形缓冲区，走独立故障槽。递归记录、嵌套冲突或空间不足采用丢弃并计数，不能阻塞业务。多核不属于首版支持范围。

首版建议默认事件缓冲区 8 KiB、故障槽 4 KiB，均由链接和配置明确分配。这是可调整的初始预算，不是所有 MCU 的适用承诺；编译产物必须报告实际 RAM/ROM 占用。耗时开销在选定板卡上分别测量关闭、开启但不发送、持续发送三种状态。

### 4.2 事件和传输

事件至少包括 `BOOT_INFO`、`CLOCK_INFO`、`MARK`、`SPAN_BEGIN/END`、`IRQ_ENTER/EXIT`、`TASK_SNAPSHOT`、`TASK_SWITCH`、`LOSS`、`CRASH_CHUNK`。固件声明事件字典版本及功能位；未提供调度钩子的固件不能声明完整调度跟踪。

UART 首版支持两种明确配置的传输模式：专用二进制通道，或文本行封装 `@HILI1 <base64-frame>\n`。混合日志模式由同一个发送仲裁器保证整帧输出不被普通日志插入；接收端仅把完整前缀、解码和 CRC 均有效的行交给插桩消费者。RTT 使用指定逻辑通道，不能抢占已有终端通道。

帧协议命名为 `HILI`，主版本 1。头部所有多字节整数采用小端；首版头长 40 字节，payload 最长 1024 字节，超限在分配前拒绝。

| 字段顺序 | 字节数 | 含义 |
| --- | --- | --- |
| magic | 4 | ASCII `HILI` |
| major、minor | 1 + 1 | 主/次版本 |
| event_type | 2 | 事件类型 |
| header_len、flags | 2 + 2 | 首版头长 40；保留标志必须校验 |
| payload_len | 4 | payload 字节数 |
| boot_id | 8 | 固件启动标识，不能单独当作全局唯一 ID |
| sequence | 4 | 每个启动代次内的事件序号 |
| ticks | 8 | 事件发生时的目标端计数 |
| crc32 | 4 | CRC-32/ISO-HDLC：覆盖前 36 字节及 payload，跳过本字段 |

CRC 参数固定为 reflected polynomial `0xEDB88320`、初值和 xorout 均为 `0xFFFFFFFF`；测试向量 `123456789` 的结果为 `0xCBF43926`。实现时同时固化至少一组完整帧的跨语言字节向量。

运行身份由 `device_id + session_id + host_boot_epoch + boot_id` 组成。`BOOT_INFO` 开启新的 host_boot_epoch，固件 boot_id 重复或不可靠时保留该事实；连接中途缺少 BOOT 信息的数据仅作未定身份记录，不能用于跨启动断言。序号按模 2³² 处理，乱序、缺口和新启动分别记录，不能把复位解释成正常回绕。

payload 按事件类型定义固定宽度字段和有上限的数组。未知次版本中的可忽略事件保留原始字节；影响时间、调度或调用配对的未知事件使相关指标失效。未知主版本拒绝解析。CRC 错误、半帧超时和噪声均输出错误与原始位置，缓冲区不得无限增长。

### 4.3 时间与丢失数据

每段时间必须附带 `clock_id`、`clock_epoch`、`tick_hz`、计数器有效位数、是否在睡眠/调试暂停时停止，以及溢出扩展是否可靠。32 位计数器可以由端口扩展为 64 位，但必须证明采样或溢出机制不会漏掉多次回绕。

变频时开启新的 clock_epoch；跨频率段的区间仅在各段映射完整时求和，否则标记无效。DWT 不作为通用前提，目标不支持时由平台提供单调硬件定时器。主机接收时间用于定位和关联，不用于计算微秒级函数耗时。

JSON 中所有 uint64 时间、计数和 ID 使用十进制字符串，避免 JavaScript 精度损失。丢失数、缓冲区覆盖和解析缺口单独记录；不把断裂的 begin/end 或调度片段拼成完整结果。

## 5. 崩溃现场保存与离线分析

### 5.1 目标端保存

故障入口首先保存原始 EXC_RETURN、MSP/PSP 和必要寄存器，再进入受限的 C 处理。入口代码需要按编译器适配并检查生成汇编，避免普通函数序言先改写待保存现场。EXC_RETURN、FPU 扩展帧和栈对齐必须按实际内核解释；未适配的架构状态返回不支持，首版不宣称支持 TrustZone 安全/非安全双现场。

每份现场包含格式版本、长度、构建 ID、启动标识、故障原因、有效字段位图、异常帧、SCB 可用寄存器、允许采集的 RAM 区间和校验信息。M0/M0+ 等目标缺少的故障寄存器不能按 M3/M4 地址集合强读。

故障栈指针、区间长度和地址溢出在读取前校验。堆栈异常、无效 SP、存储失败或嵌套故障时保留最小寄存器记录并标注缺失，不继续盲读引发第二次故障。首版不遍历外设寄存器，避免读清零和非法访问。看门狗硬复位前无法执行保存时，只报告启动时读取的复位原因，不能伪造崩溃栈。

默认保留区采用 `.noinit` 示例端口。是否跨软件复位或看门狗复位保留，必须核对 SRAM 电源域、启动文件和 Bootloader；普通 RAM 不保证断电保存。非易失存储仅预留原子提交、擦除和校验接口，首批不实现通用 Flash 故障写入。

记录先写内容、再写 CRC、最后提交有效标记，并处理平台要求的缓存维护与内存屏障。故障再次发生时不覆盖尚未确认导出的记录，使用独立计数或最小备用槽记录溢出。导出操作只读；清除必须是独立的显式操作，并校验记录 ID，不能把发送成功当作主机已持久化。

### 5.2 导出和证据包

分块导出按 `record_id + offset + length` 定位，携带总长度和完整校验。块请求是只读且可重试的；重复块必须内容一致。校验通过并落盘后，主机才提供清除入口。掉线、超时、取消时保留目标记录及主机部分文件。

证据包先使用普通目录，避免首版增加压缩包导入复杂度：

```text
evidence/<record_id>/
  manifest.json       # 格式版本、构建 ID、文件摘要、来源、完整性
  registers.json      # 有效字段、异常帧和寄存器
  regions.json        # 地址、长度、访问属性与对应文件
  memory-000.bin      # 已实际采集的区间
  events.jsonl        # 相关事件，可缺失并说明
  serial-tail.bin     # 原始日志，可缺失并说明
  analysis.json       # 符号化结果、缺失项和分析器版本
```

主机验证所有文件路径属于该目录，限制总大小、区间数和重叠映射，并核对声明长度及 SHA-256。首版默认导入上限 64 MiB、最多 64 个内存区间；调整上限需重新验证内存峰值。未完成包标为 `partial`，可查看现有证据，不满足要求完整现场的断言。

固件构建 ID 由构建流程显式写入，并与对应 ELF 一起归档；ELF 自身另存 SHA-256。默认不把源码和 ELF 自动复制进可分享目录。缺少或不匹配构建 ID 时允许看原始数据，但停止可信源码归因，不能仅凭文件名匹配。

新增 `MemorySource` 读取契约，区分实时目标和离线区间。离线分析器只能从已捕获区间及匹配 ELF 的代码段读取；RAM 缺页不补零、不回退在线连接。证据不足时降低展开结果的可信度，优化掉的变量显示不可用。

## 6. RTOS 和耗时分析

### 6.1 FreeRTOS 任务快照

首版通过 SDK 端口导出任务快照，不根据 ELF 中的符号地址猜 TCB 字段。支持的 FreeRTOS 版本、配置开关和 API 差异写入适配矩阵；其他版本报告未支持。`rtos_tracer.py` 的符号识别继续作为辅助信息，不能替代采集成功。

每条任务记录包含稳定任务实例 ID、名称、状态、优先级、栈起点、可取得的栈总字节数、历史最小剩余字节数、运行计数和字段有效位图。高水位的原始单位按 `StackType_t` 转为字节；内核不提供总栈大小时保持未知，或由创建任务包装接口显式记录，不能从高水位反推。

快照记录开始/结束 ticks、任务列表是否完整及一致性保证。任务创建/删除复用 handle 时分配新实例代次。查询在允许的上下文执行，预分配数组；任务数超过配置容量时返回不完整，不悄悄截掉后半部分。调度锁定、栈扫描带来的延迟要纳入上板测试。

CPU 占用采用两份快照间的有效运行计数增量，要求同一启动、同一时间源且已知回绕处理。计数器缺失、任务统计口径变化或区间不完整时不输出百分比。阻塞对象只在固件提供相关事件时展示；单次 Blocked 状态不自动解释为死锁。

### 6.2 函数、中断与调度事件

首版手动插入范围标记，按上下文和 token 配对，支持递归和中断嵌套。报告包含完整区间数、最小/最大/均值、分位数、超预算次数以及无效区间数。

最先交付入口到出口的总经过时间，明确可能包含中断和任务等待。仅在调度、IRQ 及时间源记录完整时计算线程实际运行时间；若需要扣除子调用耗时，还必须有完整的嵌套范围。缺失这些条件时不显示“自身 CPU 耗时”。睡眠期间停止的计数器只能提供该计数口径，不能宣称是墙钟总耗时。

预算断言指定 metric、范围 ID、阈值单位、最少有效样本数和允许的数据质量。默认存在相关事件缺口、时钟不连续或未闭合范围时返回 `INCONCLUSIVE`；超过阈值为 `FAIL`，足量且完整的数据满足阈值才为 `PASS`。零样本不通过。

PC 统计采样保持独立入口及原有语义。插桩调用次数来自有效事件；不把采样命中数写成真实调用次数。

## 7. 功耗仪器接口及分析逻辑

### 7.1 能力和会话接口

初版生产适配器注册表为空，仅提供类型、注册与能力查询、生命周期实现及明确的不支持错误。测试适配器放在测试目录，不能通过正式配置注册、自动扫描或进入真实 HIL 结果。

拟定 `PowerMeasurementAdapter` 契约如下；这是未来仪器接入边界，不代表初版能够连接设备。

| 方法 | 输入 | 输出及完成语义 |
| --- | --- | --- |
| `describe()` | 无 | 型号/驱动版本、量程、最大采样率、时间源和通道能力 |
| `open(binding, deadline)` | 固定设备 ID、连接参数 | 设备身份核验后的会话；不能默认第一台 |
| `configure(config, deadline)` | 采样率、量程、通道 | 设备确认的实际配置；不支持的值报错 |
| `start(capture_id, deadline)` | 任务 ID | 接受结果及采集状态，不代表采集完成 |
| `read_batch(cursor, limit, deadline)` | 独立游标和上限 | 有序样本、下次游标、缺口及设备状态 |
| `stop(capture_id, deadline)` | 同一采集任务 | 停止确认、最终游标、数据完整性 |
| `close(deadline)` | 当前会话 | 资源释放结果；不隐式控制电源输出 |

采集状态采用 `IDLE → STARTING → CAPTURING → STOPPING → COMPLETED`，失败进入 `FAILED`，无法确认设备是否停止时进入 `UNKNOWN`。进入 UNKNOWN 后不能立即开始下一次采集；恢复需查询真实状态或完成明确的设备恢复流程。

用户取消和正常停止保留不同的 `stop_reason`；取消请求只有在停止与资源清理得到确认后才进入 `CANCELLED`。连接状态独立记录为连接中、已连接、断开或未知，不由采集状态倒推。

底层预检区分 `driver_installed`、`device_verified`、`measurement_supported` 和 `hardware_validated`。没有驱动返回 `ADAPTER_NOT_INSTALLED`；不存在设备返回 `DEVICE_UNAVAILABLE`；配置越界返回 `INVALID_PARAMETER`。发现设备、连接成功和采集成功分别记录。

### 7.2 样本格式与离线处理

首版实现规范化文件导入及纯分析函数，不实现厂商专有文件解析。文件包含版本、仪器/数据来源、采样方法、时间单位、校准信息（可未知）、配置快照与完整性声明。CSV 导入必须提供这些元数据，不从列名猜单位。

规范化样本至少具有以下字段：

| 字段 | 契约 |
| --- | --- |
| `capture_id`、`channel_id`、`seq` | 绑定采集任务、通道和源序号 |
| `timestamp_ns`、`clock_id` | 纳秒整数十进制字符串及所属时间域 |
| `current_a` | 有符号安培值；无测量时为 null，拒绝 NaN/Infinity |
| `voltage_v` | 实测伏特值或 null，不能自动取电源设定值 |
| `quality_flags` | 丢样、溢出、量程切换无效段、时间跳变等 |
| `source_kind` | `hardware_capture`、`imported_measurement` 或 `synthetic_test` |

离线分析实现区间最小/最大、时间加权平均、有效覆盖率、电荷和能量积分。对明确为瞬时采样且同步的点，按有效相邻区间梯形积分：`Q = ∫ I dt`，`E = ∫ V·I dt`。电荷单位 C，能量单位 J；mAh 仅作明确换算 `Q / 3.6`。设备若提供区间平均值，需要声明区间边界并按对应口径积分，不能混用。

不对缺口、重复时间、时间倒退或超过配置最大间隔的样本连线积分；缺少电压只给电流与电荷，能量显示不可用。电压和电流异步时首版不自动插值相乘。电源设定电压可用于独立的显式估算，初版不实现该估算路径。

平均电流按有效时长计算，不能用不等间隔点的算术平均冒充区间均值。报告同时给出请求区间、实际覆盖区间、覆盖率和缺口数。所谓休眠电流必须来自用户指定或固件标记的区间，不能自动把最低点当作休眠值。

初版支持仪器时间域内分析以及手工锚点的日志关联，保留锚点来源、映射误差与漂移信息。没有同步证据时不提供跨设备精确延时断言。离线导入结果只生成离线分析报告，不能作为当前板卡本轮 HIL 的实测通过记录。

文件读取采用分块，统计和积分使用原始有效样本。默认单次输入上限 256 MiB、解析批次不超过 4096 点、绘图预览不超过 200000 点；分位数实现采用明确上限的精确计算或标注算法误差的近似计算。超过范围拒绝或要求用户选择较小文件，不静默截断。正式采集的吞吐和缓存策略待设备选型后按实测补齐。

## 8. 电源接口和控制状态机

### 8.1 设备绑定与命令

拟定 `PowerSupplyAdapter`，与功耗采集分开建模。某台设备同时支持两类功能时，两者共享物理资源租约和状态仲裁，不能各自创建独占会话。

| 方法 | 输入 | 完成要求 |
| --- | --- | --- |
| `describe()` | 无 | 通道、可调范围、分辨率、输出回读和测量能力 |
| `open(binding, deadline)` | 稳定设备 ID、通道、板卡 ID | 核验实际身份，不改变输出 |
| `query_state(deadline)` | 当前会话 | 输出状态、设定值、实测值及各字段有效性 |
| `apply_setpoint(op_id, settings, deadline)` | V/A 明确单位、固定通道 | 设备确认设置结果；命令发出不等于完成 |
| `set_output(op_id, enabled, deadline)` | 明确布尔值 | 设备应答及回读；区分输出使能和实际有电 |
| `cancel(op_id, deadline)` | 操作 ID | 能否取消、实际结果、是否仍占用设备 |
| `close(deadline)` | 当前会话 | 释放资源；不隐式断电或恢复初值 |

板卡配置声明允许电压、电流限制、通道用途和结束/失败/取消策略。执行范围取板卡约束与设备能力的交集；不按设备最大额定电压替代板卡安全范围。未知电流限值、不支持的设置或分辨率无法精确表达时拒绝，不静默四舍五入。

`power_cycle` 编排依次完成：确认当前状态 → 输出关闭确认 → 满足关断保持条件 → 输出开启确认 → 等待目标新的启动事件。接收窗口在可能触发 BOOT 前建立。关断保持时间从已确认的关断开始计算，不从发送命令开始计算。

只有输出使能回读而没有电压测量时，结果仅证明输出控制完成；不能证明板卡已放电或达到目标电压。实际断电测试还需验证其他供电路径、反向供电和储能。具有测量能力时使用电压阈值及连续稳定时长判断，超时则失败，不用固定等待代替状态确认。

### 8.2 状态、取消及恢复

主机操作状态采用 `IDLE → VALIDATING → APPLYING → VERIFYING → COMPLETED`；任何等待均受单调截止时间约束。设备事实独立记录为 `ON/OFF/UNKNOWN` 和设定/实测有效字段，不能把操作状态当作输出状态。

取消进入 `STOPPING`。尚未发出的步骤不再执行；已经发出的设置继续查询结果或走适配器支持的取消流程。串口/socket 超时或进程终止不表示输出已停止，无法核验时报告 `UNKNOWN`、最后确认的阶段和可能的部分完成。

操作终态区分 `COMPLETED`、`FAILED`、`CANCELLED` 和 `UNKNOWN`；只有结果可确认且取消收尾完成时才标记 CANCELLED。设备 ON/OFF 与任务是否取消分别展示，取消不等于断电。

每个运行必须显式配置 `on_success`、`on_failure`、`on_cancel`，可选 `leave_as_is`、`output_off`、`restore_initial`。没有初始可信快照不能使用恢复初值；未知状态下不得自动套用该策略。没有驱动或没有恢复能力时在启动前拒绝相应计划。关闭连接本身不执行策略。

退出策略是运行的一部分，有独立截止时间和结果；业务断言成功但要求的退出策略失败时，整轮不得为 PASS。写命令不盲目重试，操作 ID 仅用于主机去重和记录，除非设备协议证明支持，否则不承诺跨进程“恰好一次”。

为处理 worker 被终止后的情况，资源管理器在发送写命令前持久化设备绑定、操作 ID 和阶段。新任务取得设备租约后先检查未完成记录；存在 UNKNOWN 时只允许恢复查询，不继续普通写操作。没有查询能力的设备必须经过人工核验后显式解除未知状态。初版用故障注入验证流程，不提供实际电源操作入口。

## 9. 主机接口、HIL 和兼容策略

### 9.1 公共结果契约

所有新增查询与长任务通过现有 Tauri → daemon/MCP 路由，参数在 daemon 再次校验。拟定工具包括 `get_debug_capabilities`、`analyze_crash_bundle`、`analyze_instrumentation`、`analyze_power_capture` 及任务状态/取消接口；优先复用已有任务监督实现，离线分析任务不伪装成真实 HIL 运行。

结果携带以下公共字段：`schema_version`、`job_id/run_id`、设备/会话/启动身份、`source_kind`、`completeness`、`limitations`、分析器版本以及相关文件摘要。硬件验证字段需记录测试对象与证据，不能因为数据带有设备序列号就自动设为已验证。

错误保留 `code`、`operation`、`target`、`phase`、`reason`、`partial_result`、`resource_state` 和 `retryable`。工具级 MCP `isError` 必须继续沿调用链传播，不能作为普通成功结果展示。

### 9.2 HIL 动作和版本

初版底层完成后，再将已经具备执行条件的动作接入 worker：

| 拟定动作 | 用途 | 启用条件 |
| --- | --- | --- |
| `instrumentation_start/stop` | 准备接收、能力握手、采集边界和结束确认 | 已适配固件、已绑定传输与启动代次 |
| `crash_collect` | 分块读取保存现场并校验落盘 | 固件声明现场导出协议 |
| `rtos_snapshot` | 获取本次快照 | FreeRTOS 端口及命令能力匹配 |
| `instrumentation_assert` | 指定范围的耗时/事件/任务指标断言 | 数据来源和完整性满足要求 |
| `power_measure_start/stop` | 未来实时功耗采集 | 初版预留，生产驱动为空，启动前拒绝 |
| `power_measure_assert` | 未来对本轮实测区间断言 | 初版不启用真实 HIL；离线分析独立使用 |
| `power_set`、`power_cycle` | 未来电源设置和开关编排 | 初版预留，生产驱动为空，启动前拒绝 |

握手与控制请求携带 request_id，响应关联同一会话和启动代次。仅收到控制应答时改变采集控制状态；已有被动日志源不支持 start/stop 时，可定义主机观察窗口，但不得显示固件已开始/停止记录。停止采集涉及控制命令是否产生副作用必须由固件协议说明。

现有 HILv1 的 BOOT/HB/RESULT/CRASH/DONE 文本协议保持兼容，HILI 插桩数据由独立消费者解析。新增消费者使用独立游标，接收窗口在触发动作前准备；收集不能吞掉已有等待器的数据，也不能让旧启动的事件满足新步骤。

由于现有 `bench` 和步骤参数采用严格白名单，新增资源模型使用 HIL `schema_version: 3`。v1/v2 继续按原有规则读取、保留原含义，再规范化到内部模型；老版本读取 v3 必须明确拒绝。新增工位字段包含 `devices`、`bindings`、`instrumentation`、`instruments` 和 `exit_policy`，不向旧 v2 静默塞入新字段。

配置验证分为静态格式校验、无连接的驱动能力检查和执行前设备身份核验。保存未适配的设计配置可以成功，但必须标记不可运行；正式运行在任何烧录、复位和电源写操作前完成整份计划的预检。不能先执行几步，再发现电源没有驱动。

新增分析层结果为 `PASS/FAIL/INCONCLUSIVE/ERROR/CANCELLED`。接入现有 HIL 时，INCONCLUSIVE 映射为步骤 error，保留 `analysis_status` 和原因，不能扩大已有 PASS 的含义。取消沿用现有取消状态，未执行步骤继续标记 skipped。退出码和 JUnit 映射在本阶段维持既有语义。

初版不扩展同时运行多个 HIL 任务，不增加常驻系统服务。仪器和任务资源模型应可扩展，但实现继续遵守现有单运行限制。

| RTOS | 任务创建/删除/handle 复用、快照容量不足、栈单位差异、缺少总栈大小、计数回绕、无运行计数、非一致快照 |
| 耗时 | 递归、任务切换、嵌套 IRQ、丢 begin/end、零样本、跨时钟段、统计样本不足、总耗时与运行时间口径 |
| 功耗分析 | 有符号电流、不等间隔、常量/分段解析积分基准、缺电压、异步 V/I、丢样、不完整覆盖、重复/倒退时间、量程失效段、来源隔离 |
| 电源状态机 | 无驱动、通道错误、超限、不支持回读、迟到应答、取消前后各阶段、超时结果未知、恢复失败、进程中断后锁释放但未知标记仍在 |
| HIL/接口 | v1/v2 兼容、v3 拒绝与迁移、整计划预检、快速 BOOT、旧事件、断线、共享资源冲突、后台任务切页、取消和错误传播 |

跨层至少验收三条链：C SDK 固定向量 → Rust/headless 解码 → Python 耗时分析；规范化功耗文件 → 同一分析服务 → CLI/MCP 结果；HIL v3 无驱动电源步骤 → 启动前拒绝 → 无任何前置硬件写动作。故障注入用例验证真实状态转换，不复制实现算法作为测试对象。

SDK 上板验收必须记录芯片/内核、编译器、优化等级、FreeRTOS 版本、固件摘要、时钟配置、串口/RTT 带宽、最大事件速率、丢失计数、RAM/ROM 和时序开销。不能把主机生成事件的吞吐当成目标板性能。

实际代码实施后执行仓库要求的验证：

- 前端：`pnpm build`、相关生产逻辑回归；交互变化检查对应页面。
- Rust：在 `src-tauri` 运行 `cargo check --locked` 和 `cargo test --locked --lib`；新增 debug-core 测试还要针对该 crate 执行，不能默认根包已覆盖。
- Python：`python scripts/test_daemon_logic.py`、受影响的 HIL/ABC 回归和新增模块用例。
- daemon 更新：`python scripts/build_daemon_windows.py --daemon-only`，对实际冻结 EXE 验证新 CLI/MCP 和错误路径。
- 运行时代码交付：`pnpm tauri build --no-bundle`，同步版本与发布说明，使用发布脚本更新 release 和 ZIP，并执行适用的冻结程序、ZIP 清单验证。

本次仅新增设计文档，检查路径、术语、接口一致性和差异即可；不升级产品版本、不编译二进制、不重打 ZIP，也不执行任何板卡操作。

## 12. 待确定事项和默认选择

以下事项不阻塞主机底层与接口实现，但在对应硬件功能启用前必须确定。

## 13. 参考资料

以下资料用于核对技术路径，不构成默认引入第三方 SDK、商业组件或驱动的决定。首版可使用自有插桩协议；后续引入外部实现须核对许可与兼容范围。

- [SEGGER SystemView](https://www.segger.com/products/development-tools/systemview/)：目标端事件记录、任务/中断时序及传输条件。

- [Zephyr Core Dump](https://docs.zephyrproject.org/latest/services/debugging/coredump.html)：离线寄存器、内存和调试信息分析。
- [FreeRTOS 运行时间统计](https://www.freertos.org/Documentation/02-Kernel/02-Kernel-features/08-Run-time-statistics)：计数来源与运行统计前提。
- [Joulescope JS220](https://www.joulescope.com/products/js220)：电流、电压、能量测量能力参考；本方案不接入该设备。
- [labgrid](https://labgrid.readthedocs.io/en/latest/overview.html)：资源绑定和电源操作职责划分。
- [PyVISA 仪器通信](https://pyvisa.readthedocs.io/en/latest/introduction/example.html)：设备命令、完成确认和测量读取的区别；本方案不默认安装 PyVISA。
